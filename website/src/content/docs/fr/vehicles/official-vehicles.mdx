Les camions officiels s’utilisent avec des paquets `.tpv` installés manuellement. <Ui id="home-new-project" /> et <Ui id="cmd-add-vehicle" /> affichent uniquement les véhicules installés. Chaque paquet contient ses gabarits et les données du jeu : après génération, l’installation, la création d’un projet et l’export d’un mod ne nécessitent ni le jeu ni ConverterPIX.

## Générer les paquets

Les auteurs de paquets utilisent la commande Rust `tpv` avec [ConverterPIX](https://github.com/mwl4/ConverterPIX), un exécutable externe :

```sh
mise exec -- cargo run --release -p tp-pack --bin tpv -- extract "/path/to/ETS2" \
  --converter "/path/to/converter_pix" --package-version 2.0.0
```

Remplacez les chemins par votre installation ETS2 et l’exécutable du convertisseur. La version SemVer du paquet est obligatoire. Ajoutez `--vehicle man.tgx_2020` ou `--vehicle daf.2021` pour un seul camion ; sans ce filtre, tous les camions découverts sont traités. `--output <répertoire>` change le dossier parent des lots.

L’outil découvre les camions officiels ETS2, avec les DLC de véhicules et de tuning installés. Les mods utilisateur, ATS et les remorques sont exclus. Un paquet rassemble toutes les cabines et tous les accessoires peints pris en charge. Les cabines utilisent des gabarits de 4096 × 4096 ; les dimensions des accessoires viennent des définitions de peinture du jeu. Les gabarits principaux superposent les options peintes compatibles.

Chaque exécution crée un sous-dossier unique de `dist/` par défaut, contenant les paquets valides et `report.json`. Les intermédiaires et journaux du convertisseur restent sous `target/`. Les véhicules incomplets ou ambigus, shaders et UV non pris en charge sont refusés. Les autres véhicules continuent ; le moindre échec donne un code de sortie non nul. Aucun paquet partiel n’est publié.

Le rapport décrit les sources, versions, textures couvertes, réussites, échecs et limites. La validation technique ne prouve pas le bon fonctionnement en jeu : les nouveaux véhicules et configurations doivent encore être contrôlés.

`missing_dependencies` liste les références manquantes et leurs définitions sources lorsqu’elles sont disponibles. `expected_dlc: null` avec `dlc_origin: "unknown"` signifie que le DLC nécessaire ne peut pas être identifié ; l’archive mentionnant une référence ne permet pas de déterminer quel DLC la fournit.

Les affectations de peinture visant des accessoires sans définition installée sont exclues et signalées par `disposition: "ignored_reference"` ; elles n’empêchent pas la génération du paquet. Les accessoires définis dont la géométrie ou les dimensions sont inutilisables, ainsi que les fichiers requis absents, restent bloquants (`disposition: "blocking"`).

Les shaders de peinture pris en charge sont `truckpaint`, `truckpaint.tsnmap` et `truckpaint.tsnmapuv`, avec les options `airbrush`, `flipflake` et `altuv` et les suffixes de test alpha `.a` ou `.asafew.a`. Les gabarits tracent les UV du maillage ; ils ne reproduisent pas les masques d’opacité pixel par pixel. Les matériaux peints visibles des cabines doivent indiquer un même mode UV. L’extracteur applique ce mode à tous les accessoires et l’enregistre dans le paquet pour l’export du mod. Les UV sélectionnés absents ou ambigus et les modes de cabine contradictoires sont refusés. Les matériaux uniquement teintés par la couleur de base ne définissent pas de mapping UV de livrée ; une affectation visant un tel accessoire défini reste un défaut de couverture.

Les coordonnées UV finies hors de [0, 1] sont conservées, sans répétition, écrêtage ni changement de canal. Le cadre du SVG limite le maillage visible à la texture. Le rapport indique `uv_bounds` et `out_of_bounds_vertices` ; ces surfaces demandent une attention particulière en jeu. Les coordonnées non finies ou non représentables restent invalides.

`dimension_diagnostics` liste tous les accessoires dont les dimensions de découpe sont absentes ou contradictoires, avec les tailles candidates, masques et définitions/archives qui les référencent. Les masques de remplissage partagés ne déterminent pas une résolution de gabarit utile. Ces cas restent bloquants ; l’extracteur n’invente pas de dimensions.

## Installer et peindre

1. Ouvrez la [bibliothèque de véhicules](../library/) et utilisez <Ui id="vehicles-install" /> pour choisir un `.tpv` généré.
2. Dans <Ui id="home-new-project" />, cochez ce véhicule installé, choisissez cabines et accessoires, puis utilisez <Ui id="new-project-create" />.
3. Peignez et enregistrez le projet, puis suivez [Export d’un mod](../../export/mod/).

<Shot name="vehicles/library" alt="La bibliothèque de véhicules avec les paquets installés et le bouton d’installation" />

Conservez les paquets pour les réinstaller. Le jeu et le convertisseur servent uniquement à la génération. Les véhicules personnalisés et les exemples restent disponibles.

## Anciens paquets

Le catalogue Carsmaniac et le parcours par pack de gabarits sont retirés. Les nouveaux paquets conservent `official.ets2.<véhicule>`, dont `official.ets2.daf.2021`. Retirez manuellement les anciens paquets de test avant leurs remplaçants. Les placements ne sont pas migrés. Installer le même identifiant et la même version remplace cette version installée ; une autre version est conservée à côté. Les fichiers de projet existants ne sont pas réécrits automatiquement.
