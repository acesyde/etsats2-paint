## 1. Protocol crate (tp-mcp)

- [x] 1.1 Create the `tp-mcp` crate (workspace member, `tp-core` and `serde_json` dependencies, `tiny_http`) with the JSON-RPC types and the handlers for `initialize` (with the workflow `instructions`), `ping`, `tools/list` and `tools/call` (design Decisions 1 and 8); verify with unit tests that an `initialize` then a `tools/list` request yield valid JSON-RPC responses, that an unknown method returns error -32601, and that malformed JSON returns -32700.
- [x] 1.2 Define the typed requests and replies between the server thread and the app (read, render, write, with a cancellable reply slot) and the tool input schemas, including the texture id `"<package_id>/<texture_id>"` (design Decisions 2 and 4); verify with unit tests that every tool in `tools/list` has a schema and a description, and that the descriptions mention the template, texture pixels and undo.
- [x] 1.3 Parse and validate arguments into `tp-core` types on the server thread: boxes and rotations into `Frame`, hex colors and swatch references, gradients, strokes, shadows, and the caps (finite numbers, positive sizes, 10 000 path segments, objects per call); verify with unit tests: mcp-server "Malformed path data", a NaN width and a zero height are refused with a message naming the field, `#rrggbbaa` keeps its alpha.
- [x] 1.4 Convert SVG path data into `PathData` with kurbo (relative commands, arcs to cubics, several subpaths, fill rule) (design Decision 5); verify with unit tests: mcp-server "Drawing a stripe" (the bounds match the `d`), "Ring with a hole" (even-odd), and a relative `d` gives the same path as its absolute form.
- [x] 1.5 Add the HTTP server: bind on `127.0.0.1:<port>` only, POST `/mcp` with a JSON response, 405 on GET, Origin check, clean stop that fails pending requests (design Decision 1); verify with tests on a free port: mcp-server "Web page blocked", "Port in use" (bind error reported), and a stopped server refuses connections.

## 2. App side (tp-app)

- [x] 2.1 Start and stop the server from the preference, hold the channel and an `egui::Context` clone for `request_repaint`, and keep a shared status (off, listening, port in use, last call time, write calls in the last minute) (design Decisions 2 and 9); verify with a test that turning the preference on, then off, starts and joins the server thread, and that a request wakes the app.
- [x] 2.2 Drain requests at the start of each frame, except during a gesture, a text editing session, a pen path or a modal dialog; drop requests that timed out after 30 s; refuse write calls while a symbol is edited (design Decision 2); verify with kittest: mcp-server "Call during a drag" (two undo steps, ellipse after release), "Dialog left open" (call fails, nothing added later), "Symbol being edited".
- [x] 2.3 Implement the read tools (get_project, list_objects, get_object) from clones of the project; verify with tests: mcp-server "Reading a fleet" on the sample truck plus a trailer, "No project open", "Reading a path" (the `d` round-trips through add_path).
- [x] 2.4 Implement the see tools: get_template and render_texture through `tp-render` on the server thread, with `max_size` (default 1024, cap 2048, no upscale) and the scale stated in the text (design Decision 7); verify with tests: mcp-server "Seeing the result" (1024 px, "1 px = 4 texture px", the rectangle's color at its center), "Size capped", and get_template on a texture without a template fails.
- [x] 2.5 Implement add_shape, add_path and add_text: apply on a clone of the project, swap in on success, record one step with its "AI: …" label (no coalescing), select the new objects when their texture is shown (design Decision 3); verify with tests: undo-history "Undoing the assistant's change", "Two quick calls", "Interleaved with the user"; mcp-server "Drawing on another texture" and "Linking to the palette".
- [x] 2.6 Implement update_object, arrange_objects (order, group and ungroup, align, boolean ops through the existing tp-core functions), delete_objects, add_swatch, apply_style and place_symbol, with style detaching like the inspector; verify with tests: mcp-server "Partial failure", a fill change detaches the object from its style, a boolean union of two rectangles makes one path, a placed symbol follows an edit of the symbol.
- [x] 2.7 Implement import_image with `data` (base64 + name) or `path` (absolute, `.png/.jpg/.jpeg/.svg`, 50 MB cap, read once), through `import::read_bytes`, placed at the box or centered at File › Import's size (design Decision 6); verify with tests: image-import "Logo pasted in the chat", "Logo by path", "Same image twice", "Not an image" (the file is never opened), and both or neither of `data` and `path` fail.
- [x] 2.8 Check that no tool path writes to disk: grep the tool implementations for file writes, and add a test that runs every write tool on a saved project and checks the file's bytes and modification time are unchanged and the status bar shows "Unsaved changes" (mcp-server "Saving stays with the user").
